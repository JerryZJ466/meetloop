01 MeetLoop 开发与学习主计划

v3.1 | 2026-10-29 主次修订 | iOS + RN 核心；Android / Go 附加

核心只围绕 iOS 与 RN 做深。Kotlin / Android 深化和自写 Go 为附加项，不阻塞首轮实习或 RN 主项。

产品保持活动列表 → 详情 → 报名 / 取消 → 我的报名。Swift / iOS 为第一主项，TypeScript / RN 为第二主项。客户端网络、状态、鉴权失败与取消必须亲自验证；服务可先用明确标注的可控假服务 / 参考 API，不以自己完成 Go 为前提。

当前已准备尚未完成
独立公开仓库、版本管理、计划源文件、课程入口、阶段任务与验收标准。应用工程、业务实现、真机 / Release 验证、自动化测试、CI 与真实用户反馈。
本版 Markdown、HTML、PDF 内容来自同一份计划源，附官方 JD 能力审核。你的 Mac / Xcode 环境与当前独立编码水平，需要 M0 亲自验收。

这不是所有前端或所有全栈岗位的通用套餐。它直接训练移动端与跨端；通用 SDE 还需要公共基础，Web 前端需要浏览器专项。AgentDesk 的 Web 控制台可以训练可迁移的技能，两个项目不需要业务互通。

唯一执行口径

plan.source.json 是内容源，Markdown / HTML / 本 PDF 同版。旧 v3.0 和 v2.x 只作历史；本版覆盖其中将 Go / Android 列为主线前置的安排。阶段状态记录在 PROGRESS。

03 M0-M1：把 Swift 与状态写明白

M0 10-15h；M1 45-65h | 先做本地闭环，不接真实账号和后端

先修与学习

用 100 Days of SwiftUI 的语言基础与最初项目作为主课；Swift 官方指南查 Optional、结构体、枚举、协议、闭包、集合。每天课程概念立即迁移到活动业务；能过关的课程章节可以跳过。

按这个顺序开发

  • M0：安装 / 确认正式工具链，记录 macOS、Xcode 与 Swift；写 Activity 模型和筛选函数，首次 Git 提交。
  • M1：三条内存活动 → 列表和详情 → 单一数据源报名 / 取消 → 我的报名 → 空状态与错误提示。先把身份、状态与规则分离。
  • 给容量、重复报名、取消后恢复写业务断言；UI 不能靠多份独立数组碰巧同步。支持基本动态字体与按钮可访问标签。

过关后你应能

关闭教程，在 45 分钟内增加“只显示可报名活动”并保证列表与详情一致；解释值与引用、Optional、绑定、状态所有者和视图身份。展示重复点击不会重复增加本地报名记录。

首关不要求缓存、MVVM 框架、RN 或后端。能用简单结构解释状态，比提前造架构更重要。Mac 未就绪时只能先做纯 Swift / Git 练习，界面验收仍需 Xcode。

04 M2：网络、并发、缓存与排错

65-90h | 进入条件：本地四步链路独立完成

开发顺序需要掌握验收实验
Repository 与可替换数据源协议边界、错误分类、可测试依赖。用 Mock 注入空数据、错误和延迟；UI 的加载 / 空 / 成功 / 失败状态清楚。
URLSession 与并发async / await、MainActor、任务取消与生命周期、HTTP 语义。旧请求晚到不能覆盖新页面；切页取消；区分超时与服务端拒绝。
持久化与会话缓存来源、时效与迁移；令牌不写入日志，秘密进 Keychain。离线重启可读已有内容；登录失效有恢复路径；不要离线假装报名已成功。
内存和性能ARC、闭包捕获、引用链；Memory Graph、Instruments。复现并修复一个循环引用或卡顿，保留触发步骤与前后数据。

网络阶段使用可控本地假服务或参考 API，并明确来源；仍验证 HTTP、鉴权失败、超时、取消与重复请求。MG 可选阶段再亲自实现 Go / SQL 服务；客户端网络实操不能因 Go 可选而省略。

过关能力

画出请求、取消和 UI 更新的时序；从日志 / 断点定位一次旧响应覆盖；解释 weak、actor 隔离和持久化取舍。保存至少一个业务测试和一个故障回归。

Swift 语言指南 · Stanford CS193p

05 M3：UIKit 与首轮 iOS 实习

30-50h | 自写 Go、RN和Android深化均不作为首轮门槛

工作包开发内容与验收
UIKit 专项Apple Today 与官方文档：列表、导航、Auto Layout、控制器生命周期、复用；移植一个真实页面，复用自己的数据层。
ObjC 阅读 / 互操作在本阶段内留6-10h读一个小类并从Swift调用，理解ARC / bridging。深入runtime按真实JD另补。
面试作品整理应用运行、UIKit页面、网络与取消、一个内存/并发故障和回归；录3分钟演示，解释字节实习中真正掌握的工作。
独立验收60分钟增加一个报名规则；解释状态、生命周期和服务端响应含义。Mock/参考API明确标注，不把其后端写成自己的成果。

HTTP接口、错误语义与客户端行为必须理解；不要求此时先用 Go 自建账号体系、事务和数据库。自写服务放在 MG 附加阶段，避免挤占 UIKit 与 RN。

通过后可以申请匹配的 iOS 实习。M4 学 JS/TS/React，M5 做 RN；不等待 Go 或 Kotlin 专项。

Apple Today / UIKit · Swift 语言指南

06 M4-M5：React 基础到 RN 主项

M4 55-80h；M5 95-120h | RN实习作品与基本双端验证

顺序开发任务过关能力
M4 JS / TS闭包、Promise / 事件循环、模块；联合类型与运行时校验。不用 any 掩盖报名状态；解释类型检查不能验证服务器输入。
M4 React组件、状态、单向流、表单、effects 与 cleanup；先做小练习。独立改规则并修复 stale closure；区分 DOM / CSS 与 RN 组件 / 样式。
M5 独立 RN报名表单、状态、键盘、导航、网络错误；锁定当前稳定版本。真机 / 模拟器跑通，离开页面后任务与订阅正确清理。
M5 嵌入 iOS输入 activity_id 和受限会话能力；输出 completed / cancelled / needs_login / pending。回调至多一次；原生负责导航；JS 重载、重复打开与超时结果可解释。
M5 原生能力系统分享与一条原生调用链；理解 Codegen / TurboModule / Fabric / JSI 的职责。追踪 JS → 原生 → API → 回调；iOS Release 无 Metro 可启动，回归关键边界。
M5 Android基本验证用最小参考宿主完成同一RN模块的Android构建、返回和Release冒烟；先不做Kotlin完整客户端。记录实际设备/模拟器和结果；未验证Android就只写iOS宿主RN经验。

教程按项目实际 RN 版本使用，新架构与旧 Bridge 资料分开。先采用官方现有应用集成路径；Expo 可以比较，但不要同时维护多套构建路线。RN 到 Lynx 的 React / TS 知识可迁移，宿主、样式、能力接口与工具链仍需另学，当前不加 Lynx 分支。

07 选修 M6 与 MG：按需补足

Android 55-80h；Go 35-50h | 不阻塞核心投递或进入 M7

M6 Kotlin / Android 深化

  • 学习 Kotlin 空安全、数据类、协程 / Flow；Compose、ViewModel、Activity生命周期。
  • 原生列表 / 详情作为宿主，深入旋转、进程重建、取消和权限拒绝；同一RN模块再次验证。
  • 目标是解释宿主差异；不要求复制完整iOS产品，也不自动等于Android主岗深度。

MG 自写 Go 服务

  • 单体 Go + PostgreSQL，活动 / 报名 API、认证与资源权限、输入校验、迁移和日志。
  • 数据库唯一约束、容量事务、幂等键；测试重复请求、并发报名、取消、响应丢失后查询事实。
  • 选择实现时，正确性仍须验收；不引入微服务、Kafka和Kubernetes。

可以先完成 iOS + RN 的实习作品，再选一个附加项。已有参考 API 或模拟器可用于客户端训练；简历如实区分独立后端与外部依赖。

08 M7：iOS / RN 工程深化

60-90h | 不等附加的 Android / Go 完成；基础质量从早期积累

交付验收标准
测试与 CI关键业务单元、API 集成、核心端到端流程分层；锁依赖；CI 从干净检出可构建和执行对应检查。区分模拟器与真机覆盖。
性能与内存选一个真实瓶颈；固定设备、系统、构建、数据和网络；记录冷暖启动、列表流畅度 / 内存中的相关指标及重复测量。
发布与恢复iOS Archive 和 Android Release；签名、配置、权限、日志脱敏；一次坏版本 / API 兼容失败的恢复演练。外部分发按账号条件另验。
产品质量深链、可访问性、键盘与弱网；两轮 2-3 人体验，记录任务成功与问题，不伪造留存或商业指标。
面试作品包运行说明、架构图、API / 宿主契约、3 个故障案例、3 分钟演示、一次现场需求变更与独立解释。

App Store 上架、支付、IM、地图、推送和社交推荐均不属于首版必做。面试主线优先证明状态、数据和生命周期正确，功能数量不作为“扎实”的指标。

可以写进简历的边界

只写能解释和重现的行为与测量。不要把“集成了 RN”写成自研跨端引擎；不要把一台机器的并发实验写成大规模生产经验；不要把 AI 生成但尚未理解的模块当作独立成果。

11 两个项目之外必须持续训练

能力训练安排能证明什么

表达与复盘每周 30 分钟：3 分钟演示、一次故障讲解或英文方案说明。讲清问题、选择、证据与限制；区分自己完成与 AI 辅助。

Git 分支、差异审查、冲突与回滚；终端、Linux 进程 / 端口 / 日志；单元与集成测试、CI、依赖锁定和密钥管理，随着实际项目用到时练。不要把“会框架”当成已经会 SDE 基础。

  • 先不开 AI，用 45-90 分钟完成一个新规则或工具；允许查官方文档。随后可以让 AI 审查差异。
  • 拿一个未提前看答案的故障，写出复现步骤、假设、修复与回归。未通过就缩小任务补练，不能只重新播放课程。
  • 普通业务与数据结构面试仍要练；数学不强不妨碍这条应用工程路线，但不能跳过复杂度、基础概率和测量思维。

13 起步、复盘与防止走偏

今日先做 M0；具体时间块见 START_HERE.md

  • 先用 45 分钟写一个不依赖 AI 整段生成的 Activity 筛选 / 容量规则练习。记录不会的语言点；不要因为有四个月实习就跳过验证。
  • Mac 可用：建立最小 SwiftUI 工程并显示三条活动；Mac 未就绪：完成纯 Swift 和 Git，等待环境后再计 UI 关卡。
  • 第一周按 13h：诊断 / 环境 3h、课程与练习 3h、本地模型和列表 5h、测试 / 复盘 2h；若 M0 未过，后续工时补 M0。
