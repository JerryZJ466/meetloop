# 学习时间与面试验收

评估日期：2026-10-28。以已有 4 个月 iOS 实习、需要补独立编码与基础、Agent 工程从基础练起为前提。没有通过代码审查或现场测试测定当前能力，因此以下是任务拆分后的个人规划估算，不是行业统计或录用承诺。

时长均为**从现在起累计的有效学习时间**，包含课程、阅读、实现、调试、测试和复盘；各档不能相加。每周另留 3 小时公共基础与面试练习，已计入总计 21 小时。正常查资料和返工包含在范围内，考试、搬家和整周暂停会延长日历。

| 项目与目标 | 累计投入 | 按当前项目时间折算 |
| --- | --- | --- |
| MeetLoop：开始面试 iOS 日常实习 | 180-260 小时 | 11h/周，约 4-6 个月 |
| MeetLoop：iOS + RN 主项较扎实，具备 Kotlin 宿主和最小后端能力 | 450-650 小时 | 11h/周，约 10-14 个月 |
| AgentDesk：能面试部分 AI 应用 / Agent 实习 | 250-350 小时 | 7h/周，约 8-12 个月 |
| AgentDesk：主线较扎实，可谈权限、恢复、评测与交付 | 400-550 小时 | 7h/周，约 13-18 个月 |

日历按每月约 4.33 周计算。Agent 后续提高到 8-10h/周时，进度会缩短；总周投入不变时，需相应调整 MeetLoop 的时间。主线文档中的 400 小时应视为较顺利情况下的下限。

## 周投入与近期重点

默认 11h MeetLoop + 7h AgentDesk + 3h 公共基础。当前若把 2027 年 3 月左右开始实习作为第一目标，可阶段性改为 13h + 5h + 3h，优先把 iOS 项目讲清楚。到达 iOS 关卡后恢复双线推进。

从 2026 年 11 月到 2027 年 2 月底约 17 周，按 13h/周约有 221 小时 iOS 训练空间；这是准备 iOS 实习的合理冲刺窗口，仍需考虑春节与学校安排。不必等 RN、Android 和 Agent 全部完成才开始投递，也不把未完成内容写成已掌握。

公共 3 小时建议：2 小时数据结构 / 算法、HTTP / 网络、OS / 并发或 SQL 的薄弱点；1 小时项目讲解、简历与模拟面试。两个项目能共享这些知识，不能替代这些基础。

## 时间之外的通过标准

达到时长只触发一次验收，不自动算过关。能独立解释、实现变更、定位故障并提供验证证据，才进入下一档。建议每 4 周做一次不依赖 AI 整段生成的现场演练；若失败，记录卡点并补 2-4 周对应实验。

两条主线在持续投入下，按 12-18 个月建立较扎实的面试作品组合是合理目标；较高时长端或停学较多时需要更久。更早可先用通过验收的一项申请实习。

## MeetLoop 的 450-650 小时怎么花

| 工作包 | 估时 |
| --- | --- |
| Swift / SwiftUI / UIKit、独立交付和基础调试 | 180-260h |
| JS / TS / React / RN 与 iOS 集成 | 130-180h |
| Kotlin / Android 宿主与生命周期 | 40-60h |
| Go、HTTP 契约、权限、SQL、事务与幂等 | 30-50h |
| 综合可靠性、性能、发布、反馈与项目案例 | 70-100h |

180-260 小时的第一档主要面向 iOS 实习，不等于已经完成 RN 主项。原生能力、RN 集成和跨层故障都应放在后续累计时长内完成。

## iOS 实习面试关卡

- 45-60 分钟内独立增加活动筛选或报名规则，并解释状态存放与边界。
- 讲清 ARC、闭包捕获、Optional、值 / 引用、UIKit 生命周期、SwiftUI 状态和基础任务取消。
- 复现并修复旧请求覆盖页面、重复提交或循环引用中的至少两个问题。
- 演示网络加载 / 空 / 错 / 成功状态；核心规则有可重复的测试。
- 用 5 分钟讲清一项真实实习工作和一个项目案例，区分自己理解的部分与 AI 提供的帮助。

## 完整主项关卡

- RN 模块在两个宿主中正确进入、退出、回调和刷新；能解释 React 状态、effect 清理与原生模块契约。
- 能从用户点击追踪到 Swift / Kotlin、RN、Go、数据库，再解释结果如何更新界面。
- iOS / Android Release 可运行；有一个原生能力适配，至少一次生命周期相关跨端排错。
- 有一份固定条件下的性能或内存测量、两轮用户反馈和三项工程案例。
- 不要求精通所有 Android 页面、Flutter、Lynx 或 Go 分布式系统。针对具体岗位再补专项。
